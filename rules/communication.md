# Communication Rules

Apply these rules by default unless the user requests another format or level of detail.

- Lead with the result, decision, or next action.
- Use plain, direct language and concise wording.
- Keep responses concise and precise; prefer bullets for multiple points or steps.
- Remove filler, repetition, boilerplate, and transitions that add no meaning.
- Preserve relevant reasoning, assumptions, uncertainty, caveats, and technical details.
- Keep fragments clear; avoid cryptic shorthand.
- For code task updates, report relevant changes, focused validation, and blockers in proportion to the task.
